## 1.2.0 개발판: Steam 빌드 25244463 대응

새 빌드의 실행 파일, 50층 진입 맵, BrgGame 패키지를 인식하도록 추가했습니다. 새 실행 파일에서 메뉴 예약·키 입력·에스컬레이터 이동 위치를 다시 확인하고 패치를 생성했습니다. 업데이트된 맵의 재질 데이터는 보존합니다.

- Node.js 18 이상과 `run.bat` 사용 방식은 동일합니다.
- 복사본에서 적용·제거·전체 백업 복원 후 대상 4개 파일의 SHA-256 일치, 원본 설치 파일 미변경을 검증했습니다.
- 생성된 이동 코드의 101·201·301층 예약, 51층 기본 동작, 다른 경로 통과, 방향키·Enter 입력을 에뮬레이터로 검증했습니다. **실게임에서 메뉴 조작·실제 층 이동은 아직 확인 전**이므로 시험 적용 동의가 필요합니다.
- 이번 새 빌드 지원 대상은 확인된 기본 패키지(`3877130C584B2CBABB89A22DF1E7A0E437496B37`)입니다. **25244463의 저스트가드·M2G 수정본 병용은 아직 지원하지 않습니다.** 아래 1.1.x 병용 안내는 빌드 25136512에 해당합니다.
- 이전 빌드 지원은 유지하며, 업데이트 전 백업을 새 빌드에 복원하는 것은 차단합니다. 세이브·MASTER DB·22층 엘리베이터는 변경하지 않습니다.

## 1.1.2 변경: 구버전 M2G 인식 및 제거 순서

구 M2G v1.0.0 적용본 8종도 지원합니다. 제보된 `E6954465DE2011C2B80E224AE86823B3DB7221B5`를 인식하며 이미 정상 적용된 워프는 재적용하지 않습니다. 워프를 켜거나 끌 때에는 나이프 기능을 유지하면서 검증된 Node.js 형식으로 재생성합니다. 추가 런타임 설치는 필요 없습니다.

**M2G 도구 v1.2.0의 4번 ‘M2G만 제거’**와 함께 사용하면 어느 패치를 먼저 제거해도 됩니다. M2G 도구의 3번은 선택 제거가 아니라 과거 파일 전체 복원입니다. 구형 도구 대신 두 도구의 최신 폴더 전체를 받아 사용하고 기존 백업은 보관하세요.

## 1.1.1 변경: M2G 나이프 모드 적용 순서 호환

Steam 빌드 `25136512`에서 **M2G 나이프 모드 Node.js v1.1.0을 먼저 적용했어도 워프를 적용할 수 있습니다.** 반대로 워프를 먼저 적용한 뒤 나이프 모드를 적용해도 됩니다. 기존 나이프 도구를 바꿀 필요 없이 이 워프툴을 업데이트하세요.

- 순정 및 현재 저스트가드의 그로기/근접 방어 제한 ON·OFF 4가지 조합을 지원합니다.
- 워프 상태 화면에 `M2G 나이프` 적용 여부를 함께 표시합니다.
- 이 도구의 **패치 제거**는 M2G 나이프를 유지하고 워프만 제거합니다.
- 제보된 SHA-1 `F0439B6D568FF02E0E9488F4ED6323056C84F842`를 지원합니다.
- 확인된 파일만 처리하며 SHA-1뿐 아니라 변환 전후 SHA-256도 검증합니다. 알 수 없는 수정본을 강제로 허용하지 않습니다.
- Node.js만 사용합니다. 추가 설치는 필요하지 않으며 `compat/` 폴더도 함께 받아야 합니다.

**전체 백업 복원은 패치 제거와 다릅니다.** 백업 당시의 파일 전체로 되돌리는 기능입니다. M2G 도구의 기존 전체 백업 복원 안전장치도 그대로이므로, M2G 적용 뒤 워프 상태를 바꿨다면 해당 도구에서 복원이 차단될 수 있습니다. 그 경우 워프를 M2G 적용 당시 상태로 되돌린 다음 복원하세요. 백업을 지우거나 해시 검사를 우회하지 마세요.

호환성 자동 테스트와 복사본 검증 기록은 [M2G 호환성 검증](M2G-COMPAT-TESTING.md)을 참고하세요. 임의 수정본까지 허용하지는 않습니다. 아래 새 빌드의 실게임 검증 표시는 별개로 유지합니다.

> 1.1.0 개발판: 2026-09-08 Steam 빌드 `25136512` 대응을 추가했습니다. 새 빌드는 복사본 적용·제거 및 코드 에뮬레이션 검증 완료, 실게임 검증 전입니다. 메뉴 1번에서 경고에 동의해 시험 적용하거나 CLI에서 `--experimental`을 사용하세요. 이전 빌드의 1.0.9 검증 기록과 구분합니다.

새 빌드를 자동 인식하며 이전 빌드 지원도 유지합니다. 저스트가드 새 빌드 대응판과 함께 사용 시 설정 변경 후에도 워프와 중앙 메뉴를 보존합니다. 업데이트 전 백업을 새 빌드에 복원하는 동작은 차단합니다. 업데이트 뒤에는 현재 게임 파일로 새 백업을 만드세요.

## 사용법

1. LET IT DIE를 완전히 종료합니다.
2. [Node.js](https://nodejs.org/) 18 이상을 설치합니다.
3. 이 저장소를 ZIP으로 내려받아 압축을 풉니다.
4. `run.bat`을 실행합니다. 관리자 권한 창이 뜨면 허용합니다.
5. 메뉴에서 `일반 텐고쿠 시작층 선택 적용`을 고르고 적용 확인에 `y`를 입력합니다. 변경 전 파일은 자동 백업됩니다.

Steam이 다른 드라이브나 임의 경로에 있어도 Steam 라이브러리 목록을 검색합니다. 자동 검색에 실패하면 LET IT DIE 설치 폴더, `BrgGame-Steam.exe`, `BrgGame.upk` 중 하나의 경로를 직접 붙여 넣을 수 있습니다.

## 동작 설계 (모든 시작층 사용자 실게임 확인 완료)

일반 텐고쿠 입장 확인 및 소지품 검사 뒤 메뉴에서 목적지만 메모리에 예약하고, 기존 문 열기 연출과 입구 맵은 유지합니다. 출구 에스컬레이터에서 원본 이동 처리가 정상 목적지를 계산한 다음, 출발층·출발 구역·목적 구역·도착 유닛을 검사하고 목적층만 101·201·301층으로 변경합니다. 이후 원본 맵 생성 처리를 계속합니다. `DebugStartFloor`나 엘리베이터 우회는 사용하지 않습니다.

선택 항목은 화면 중앙에 표시되며 키보드의 위·아래 방향키로 항목을 옮기고 `Enter`로 확정할 수 있습니다. 게임패드의 방향 입력과 결정 버튼도 그대로 지원합니다.

정확히 100·200·300층이 아니라 101·201·301층을 사용하는 이유는 100층 단위 지점이 보상/대기용 특수층이고, 그 다음 층이 정상적인 전투 시작층이기 때문입니다.

## 안전장치와 복원

### 2026-09-06 메뉴 이동 잠금 변경

시설 상호작용 상태를 이용한 첫 수정은 실게임에서 이동을 막지 못해 폐기했습니다. 현재 버전은 메뉴의 `PlayerInputDisable`을 켜 컨트롤러 `OnInput`을 차단하고, 원본 UI 입력 마스크에는 메뉴 활성 중에만 ↑·↓·Enter·Esc를 추가합니다. 원본 WASD/패드와 반복 입력 계산은 유지합니다. 전역 키 설정 파일은 바꾸지 않습니다. 선택/취소 마커가 키보드 연결을 해제하고 메뉴 종료 시 원본 Tick이 캐릭터 입력을 다시 켭니다. 가드 분기 복구본도 그대로 보존합니다. CPU 에뮬레이션 5개 테스트와 복사본 갱신→백업 복원 후 네 파일의 정확한 해시 복귀를 확인했습니다.

2026-09-06 사용자가 메뉴 이동 잠금·키보드 조작에 이어 모든 시작층의 실게임 정상 작동을 확인했습니다. 이 결과를 반영해 개발판 적용 제한을 해제했습니다. 이는 사용자 테스트 결과이며 모든 설치 환경에 대한 호환성을 보장하지는 않습니다. 파일 해시 검사와 자동 백업은 그대로 유지합니다.

- 적용·제거·복원 전에 `BrgGame.upk`, `Heaven_A01_ST_COL.upk`, `BrgStart_PL.upk`, `BrgGame-Steam.exe`를 함께 백업합니다.
- 임시 파일의 SHA-1을 확인한 뒤 네 파일을 일괄 교체합니다. 파일 해시 일치는 실게임 이동 성공 검증을 대신하지 않습니다.
- 교체 중 실패하면 원본 이름으로 자동 롤백합니다.
- 메뉴의 `패치 제거`는 알려진 순정/저스트가드 조합을 유지하면서 이 기능만 제거합니다.
- `최신 백업 복원`으로 직전 상태를 통째로 되돌릴 수도 있습니다.

백업은 도구 폴더의 `backups` 아래에 저장됩니다. Steam 파일 무결성 검사를 실행해도 원본으로 복구됩니다.

### 1.0.9 변경 사항

- 선택값을 세이브/DB/공용 `StartFloorName`에 쓰지 않고 별도 메모리에 보관합니다.
- 일반 텐고쿠 51층의 정상 출구 조합에서만 예약값을 한 번 소비합니다. NEO 선택은 예약을 해제합니다.
- `BrgStart_PL.upk`는 변경하지 않습니다. 실행 파일의 확인된 세 지점에 예약/목적지 처리와 메뉴 전용 키보드 입력 코드를 연결합니다.
- x64 코드 에뮬레이션에서 세 고층, 기본 진행, 잘못된 예약, 다른 출발층/구역 및 NEO 제외를 검사했습니다. 임시 설치본 적용·제거 후 네 파일의 원본 해시 복귀를 확인했습니다.
- 일반 적용: `node lid-tengoku-warp.js apply --yes --game "설치 폴더"`. 게임을 종료하고 사용하세요. 이전 명령과의 호환을 위해 `--experimental`도 계속 인식하지만 더 이상 필요하지 않습니다.

### 1.0.8 개발 상태

- 문 열기 이벤트와 실제 층 이동 이벤트를 구분했습니다.
- 준비 중이던 `StartFloorName → FloorSelect` 연결은 엘리베이터용 이벤트로 이어지므로 폐기 대상입니다. 정상 에스컬레이터 이동이라고 간주하지 않습니다.
- 정상 `MoveFloor` 요청은 출발 구역·유닛 정보를 전달합니다. 고층 목적지를 실제 다음 층 생성에 반영하는 부분은 미완성입니다.
- 잘못된 연결의 재적용을 막는 개발판 적용 차단을 추가했습니다. 복원 기능은 유지합니다.

### 1.0.7에서 확인된 문제

- 고층 시작 시 존재하지 않는 동적 구역 유닛을 사용하지 않고 실제 텐고쿠 시작 맵을 생성하도록 변경했습니다.
- 선택한 고층의 FloorID와 51층 입구 맵 정보가 충돌해 입구 맵 일부만 로드되는 문제가 남아 있었습니다.

### 1.0.6에서 변경된 내용

- 101·201·301층을 고정 맵으로 직접 전환하지 않고, 선택한 층을 예약한 뒤 원래 일반 텐고쿠 진입 이벤트를 실행하도록 변경했습니다.
- 이 방식만으로는 절차 생성 상태가 만들어지지 않아 고층 선택 시 허공으로 진입하는 문제가 남아 있었습니다.

### 1.0.5에서 수정된 문제

- 메뉴 좌표를 바꾸면서 스크립트 크기가 증가해 시작 시 `Script serialization mismatch`가 발생하던 문제를 수정했습니다.
- 좌표 상수와 좌표 참조만 같은 바이트 길이로 교체하도록 중앙 배치 방식을 바꿔 스크립트 크기와 정렬을 보존합니다.

### 1.0.3에서 수정된 문제

- 시작층 선택 메뉴를 화면 왼쪽 위에서 중앙으로 옮겼습니다.
- 메뉴 표시 중 플레이어 입력을 잠그지 않도록 하여 위·아래 방향키와 `Enter`가 정상 작동하게 했습니다.

### 1.0.2에서 변경된 내용

- 51층 선택은 디버그 이동을 거치지 않고 원래 일반 텐고쿠 진입 이벤트를 사용하도록 변경했습니다.

파일 해시가 알려진 프로필과 다르면 변경하지 않고 SHA-1을 표시합니다. 다른 게임 버전에 억지로 적용하지 않습니다.
