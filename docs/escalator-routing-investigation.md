### 사용자 저스트가드 수정본 호환 및 적용 (2026-09-05 17:24)

사용자가 정상 작동을 확인한 `BrgGame.upk` SHA-1 `266C9712F6E9EB4FB30110D078BC0377B678B30B`를 별도 프로필로 추가했다. 이 파일에는 중앙 UI가 이미 있어 세 좌표/참조 시그니처를 확인하고 패키지 전체를 그대로 보존한다. 실행 파일의 애니메이션 패키지 해시 변경도 별도 네이티브 프로필로 보존하며, 기존 프로필은 삭제하지 않는다.

복사본 적용·제거 후 네 파일이 모두 바이트 단위로 원복됨을 해시로 확인했다. 게임 종료 확인 후 실게임에 적용했으며 변경 전 백업은 `backups/20260905-172458-601`이다. 적용 전후 BrgGame, AS_CH_Main_Male_Common_SF, BrgStart_PL, masters.db, 세이브의 SHA-256은 모두 동일했다. 실제 101층 도착 검증은 아직 남아 있다.

- 오프라인 Movefloor 핸들러를 따라 `0x141171b00 → 0x14120f260`의 정상 이동 경로를 확인했다. 연결 조회 성공 직후 RVA `0x120f66a`에서 원본 목적지 FString을 검사한다. 이미지 기준 주소는 `0x140000000`이다.
- 51층 `HVN_FLR_0001 / HVN_AREA_000`에서 정상 목적지 `HVN_FLR_0002 / HVN_AREA_016 / D0`일 때만 목적층을 `0051/0151/0251`로 변경한다. DB에서 이 세 목적층도 `HVN_AREA_016`을 사용하는 것을 확인했다. 도착 구역·유닛은 그대로 두고 정상 상태 설정과 생성 코드로 복귀한다.
- 메뉴는 `SetGameFlagNT` 호출 지점 RVA `0x1086547`에서 정확히 일치하는 전용 마커만 가로채 예약한다. 실제 세이브 플래그를 쓰지 않는다. 일반 플래그는 원래 가상함수로 전달한다. NEO 메뉴와 기본 시작 선택은 예약을 지운다.

- `BrgStart_PL.upk`는 순정 그대로다. 과거 `StartFloorName → FloorSelect` 실험은 재사용하지 않았다.

## 로컬 원본에서 확인한 사실

- `Heaven_A01_ST.upk` export 2535의 `MM_96_Hazama`는 플레이어 모드, 성별 분기, 문 열기 Matinee(2530/2531), Toggle로 이어진다. 층 로드 이벤트가 아니다. 이전 README의 “메뉴 선택 후 51층을 로드” 설명을 정정했다.
- `BrgStart_PL.upk`의 `GoalEscalatorStepOn`(4573) → `IsInHub`(3691) False → `MoveFloor`(3571)가 원본 출구 이동 흐름이다.
- 준비하던 우회 대상 `FloorSelect` switch(4473)는 GetFloorInfo/CompareString/Fade 이후 `BrgUseElavator`(4278)로 이어진다. 에스컬레이터의 검증된 고층 전환 경로가 아니므로 적용하면 안 된다.
- `BrgGame.upk`의 `BrgNetworkManagerCustom.RequestMovefloor`는 플레이어 위치로 출발 유닛을 구하고 연결 유닛명과 현재 구역을 요청에 넣는다.
- `BrgGameBase.upk`의 `BrgDbMoveFloorParam`에는 soul, fromunit, fromarea가 있다. 정상 `RequestMovefloor`는 이 구조체를 `mv` JSON으로 직렬화한다. 직접적인 목적지 필드는 확인되지 않았다.
- 반면 `BrgDbDbgMoveFloorParam`에는 toflrid/toareaid/torefareaid/tounit/lvl이 있다. 디버그 API를 호출하는 것만으로 정상 절차 생성이 보장되지는 않는다.
- `StartFloorName`은 기존 게임의 공용 변수다. 독립적인 패치 전용 예약값으로 간주하면 안 된다.

## 폐기할 개발 실험의 추가 결함

미적용 `dev/patch_brgstart_floor_redirect.py`는 임의의 비어 있지 않은 StartFloorName을 전역 출구에서 처리하며, 현재 층/허용 목적지 검사가 없다. 신규 CompareString의 오브젝트 번호도 기존 export와 중복된다. 이 스크립트와 현재 미검증 자산은 배포 근거가 아니며, 새 빌더는 이 경로를 재사용하지 않아야 한다.

## 읽기 전용 분석 도구

`dev/inspect_native_travel.py`는 백업 EXE의 PE 예외 테이블로 함수 범위를 찾고 RIP-relative 문자열 참조를 표시한다. `--function`과 `--near`로 범위를 좁힌다. 실행 파일을 쓰거나 프로세스에 주입하지 않는다.

`movefloor` 문자열 참조는 이미지 기준 함수 0x141103650 및 0x140e256e0에서 확인했으나, 목적지 결정을 담당하는 함수라는 증거는 아직 없다. 0x141103650은 이름/번호 등록 코드 형태이며 0x141591740은 DB 스키마 등록 코드 형태다. 실제 이동 핸들러로 오인하지 않는다.
